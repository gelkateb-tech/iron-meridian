# Building Iron Meridian

One source, two builds:

```
node tools/build.js
```

| Build | Folder | What it has | Use it for |
|---|---|---|---|
| Test | `dist/test/` | the game, developer mode, and the test hooks (`window.__im` on `file://`) | playtesting and the automated tests |
| Public | `dist/public/` | the game only. Every developer and test block is removed at build time. | **publishing** |

Each folder is a complete copy: `index.html` (the page to publish), `play.html` (the same page in a full HTML document, so you can open it locally), `world.js nations.js lines.js coast.js coast-hi.js units3d.js fx.js`, the rules files `rules/*.js`, and `assets/` (without `assets/art-src`, the source art the game never loads). The assets are hard-linked to the source files where the file system allows, so they take no extra disk space. Do not edit files inside `dist/`, because a hard-linked file is the source file. `dist/` is in `.gitignore`.

**To publish, use `dist/public`:** publish `index.html` as the page, plus these files at the same relative paths. Do not publish `play.html`.

| Files | What they are |
|---|---|
| `world.js` `lines.js` `coast.js` `coast-hi.js` | map data |
| `nations.js` | the playable nations of the nations world (generated by `tools/build-nations.js`; see "The nations world" below) |
| `rules/core.js` `rules/data.js` `rules/map.js` `rules/state.js` `rules/research.js` `rules/production.js` `rules/economy.js` `rules/trade.js` `rules/movement.js` `rules/diplomacy.js` `rules/territory.js` `rules/combat.js` `rules/air.js` `rules/vision.js` `rules/ai.js` `rules/tick.js` `rules/api.js` | the game rules, 17 files (publish every `.js` file in `dist/public/rules/`) |

| `fx.js` | the map effects (battle fire, strikes and blasts, particles, battle smoke) |

## The nations world

The start screen offers **Nations of the world** only (scenario key `world64`, all 68 nations; `docs/NATIONS-PLAN.md`). The **classic** world (the 15 powers on the old rules, scenario key `world`) left the start screen once every region was open (owner's answer 3), but it stays in the rules: every old save is a classic game and continues and plays as before (Continue, the save slots). Test pages (file://, test build only: `pickClassic` in `index.html`, inside a `@TEST` block) keep the switch between the two worlds and open on the classic one, so the classic-world tests still start classic games by the start screen; `page.html?start=nations` shows a test the start screen as players see it (`.test/nat-world.js` checks it, and that a classic save continues and plays; `.test/public-smoke.js` checks the public build's).

- `nations.js` (`window.NATIONS`) lists the playable nations of the nations world: name, map country, region, tier (S, A, B, C), colour, capital and cities (province numbers of `world.js`, capital first). It is written by `node tools/build-nations.js` from the roster and the city-choice method in that tool and is never edited by hand. A rollout step opens a region by adding it to `OPEN` in the tool (and the colours and city names of its nations), then runs the tool. `--check` fails when the file on disk is not what the tool writes; `--preview` prints the cities the method picks for every nation of the roster.
- `world.js` is not changed. Which provinces are cities and capitals is switched per game by `useWorld` (`rules/map.js`): the flags of `world.js` for the classic world and every old save, the lists of `nations.js` for the nations world. A nations-world save carries its own list of cities (`S.w64`), so it keeps its world when `nations.js` grows; a save of a newer format than the build knows is refused with a message (`restore.why`).
- The tier rules are in `rules/`: the start by tier (`tierStart`, `tierCatchUp` in `rules/state.js`; the numbers are `TIER_EVEN`, `TIER_FULL` and `TIER_MODES` in `rules/data.js`), the grace by tier gap (`graceOn`), the computer's choice of victim and its limit on wars (`rules/diplomacy.js`), the victory numbers by the number of nations (`winCapsFor`, `winShareFor`, `coalCaps`). A game mode sets how far apart the tiers start: `spread` 0 is an equal start for everyone, 1 the plan's wide table. Normal mode is 0.3 (close to equal); `competitive` (0.6) is in the table for later and not offered yet.
- **Province split** (owner's answer 1; plan 4.6): the nations world plays on its own map, `world.js` with Israel, Greece, Cuba and Belarus cut into smaller provinces (21 new provinces, numbers 3465 to 3485, appended after the last province of `world.js`; each records the province it was cut from, `P.parent`). `node tools/build-provsplit.js <ne_10m_admin_1_states_provinces.geojson> <ne_10m_populated_places_simple.geojson>` (Natural Earth; `NODE_PATH` with `country-state-city` for town names, as for `tools/build-world2.js`) writes `tools/provsplit.json`: the new provinces (name, country, people, terrain, parent), the cut provinces' new name, people and terrain, the cells that move, and the river, road and rail pairs that touch a cut province (worked out from the lines of `lines.js` with the rules of `tools/build-lines.js`). `tools/build-nations.js` copies it into `nations.js` as `NATIONS.map` and chooses the cities on that map. `node tools/build-provsplit.js --check` checks the file against `world.js` and `lines.js` without the Natural Earth files.
- **Two maps**: `rules/map.js` keeps map 0 (`world.js` as it is: the classic world, the theatres, every old save and a nations-world save made before the split) and map `MAP_NEW` (with the split), each loaded once when first needed (`mapOf`); `useMap` makes one the map in use (`G`) with a new game or a load. A save names its map (`S.map`; absent for `world.js`). On the split map every province of `world.js` keeps its deposits, city ground, sea straits and the per-province yield scale exactly as on `world.js`; only the new provinces draw their own. The page hears `world` and hands the terrain texture, lakes, land mask and sea from one map to the other, and makes again what hangs on provinces (lines, lake-side labels, every town's footprint and bakes, trays, the cached layer); the start screen counts the nations world on its own map (`onMap`).
- **Regions open** (step 6, all of them): Europe, with Greece and Belarus on the split map, the Middle East, with Israel on the split map, Africa, Asia, the Americas, with Cuba on the split map, and Oceania (68 nations). In the nations world a computer nation at peace and away from every person's nation plans every 8 hours instead of 4 (`aiAway` in `rules/tick.js`, plan 3.7); a computer nation goes for independent land only below 1.5 times its starting land and, holding twice its start, makes peace, starts no war, halts its columns on foreign land, annexes no collapsed nation and only takes back its own lost land (`TIER_FREE`, `TIER_SATED` in `rules/data.js`; `isSated` in `rules/diplomacy.js`); from day 60 both limits grow (`tierGrow`, `TIER_LATE`). Two nations of tier S or A go to war with each other at 0.95 times the other's power instead of 1.1 (`TIER_PEER`). A computer nation of tier S or A already at war with one of tier A takes on another of tier S or A only with the power for both (`TIER_FRONT`), and two computer rivals of tier S tire of their war after 60 days instead of 20 (`TIER_RIVAL_WAR`, `warTires`). Whom a computer nation attacks, by tier (`TIER_DOWN_A`, `TIER_UP`, `TIER_BULLY`): a superpower takes on a major power only with 1.6 times its power, anyone else takes on a superpower only with 1.3 times, a nation two tiers above its victim only with twice; the peer threshold is for nations of one tier and an attacker one tier above; a superpower starts a war only while in at most one of its own (`TIER_WARS`). The land to win is a share of the world that falls as nations are added (`winShareFor`): 7% of the world from 60 nations, 6% with all 68 (185 provinces), and at least the starting land plus 90 or plus half of it (`TIER_WIN_UP`). `node tools/nations-balance.js` runs the plan's tests 5.2 and the checks of every step done (5.4); `node .test/nat-europe-shots.js <dir>`, `node .test/nat-me-shots.js <dir>`, `node .test/nat-africa-shots.js <dir>`, `node .test/nat-asia-shots.js <dir>`, `node .test/nat-americas-shots.js <dir>` and `node .test/nat-oceania-shots.js <dir>` take each step's screenshots (the region's tab, the region at the opening zoom, a phone) and check every city of the region is on the map under its name. Oil, one rule in both worlds: a country with 8 or more cities and no oil city has its smallest city of its most common resource made an oil city (`cityMains`, `rules/map.js`: Port Hedland in the classic world; in the nations world 11 nations of 8 to 11 cities, Australia, Spain, Poland, Romania, Greece, Mozambique, South Korea, Myanmar, the Philippines, Bolivia and Cuba); then a nation of the nations world whose starting cities still make none of oil, materials, iron or electronics gets twice the capital's share of it (the state reserve: `ECO_RESERVE`, `N.reserve`, set in `tierStart`; with the oil cities above only Norway and Mongolia, for electronics); `node tools/eco-check.js` (more than 4,000 oil, materials and iron a day for every nation on day 1, in every world) belongs to every step's checks. A nations-world save is packed (`packOut`/`packIn` in `rules/state.js`, `S.pk` 1): a relation is stored only once it differs from the default peace, and the per-province lists of building work, captures and occupation only where they hold something; a new game's save is 250 KB with 68 nations (test T11: under 300). `node .test/nat-play.js <days> <nation>` plays any nation from its region's tab with no console error allowed (New Zealand and Mongolia, 10 days each, plan 5.4).
- Nothing of this runs in the classic world: `node tools/split-golden.js 20` (it starts its game on the classic world, `useScenario('world')`, whatever the start screen shows), `node tools/headless.js --check` (the same state hash as master before the merge) and `node .test/nat-oldsave.js` (a save made by the build before the nations world, master 8d9051c in `.test/base8d9`, plays on to the same state in the old and the new build) prove it. The browser tests pick their nation by name (`.test/pick-nation.js`: on the nations world it tries each region tab), so they work on either start screen. `node .test/nat-world.js` goes back and forth between the two maps in one page; `node .test/nat-split-shots.js <dir>` shows the four countries on both maps and taps the new provinces.

## Rules files

The game rules live in plain scripts in `rules/`, not in `index.html` (owner task 5, finished in step 10). The page loads them with `<script src="rules/x.js">` after the map data and before its own script, in this order:

| File | What it holds |
|---|---|
| `rules/core.js` | the namespace `IM` and its event sink (`IM.on` / `IM.emit`); seats (`isSeat` `seats` `desk`); the reports, each addressed to a seat (`tell` `tellAll` `refuse` `cue` `alarm` `fxAt` `bump`) |
| `rules/data.js` | tables and constants (units, missiles, resources, terrain, buildings, research, doctrines), the seedable dice `rng()`, hex-grid maths |
| `rules/map.js` | the world: provinces, neighbours, straits, links, resources, seasons and weather |
| `rules/state.js` | scenarios, `newGame`, `saveJSON`, `restore` and the old-save upgrades |
| `rules/research.js` `rules/production.js` | research slots; costs, building, mobilizing, training |
| `rules/economy.js` `rules/trade.js` | yields, income, market and order book, unrest; trade routes, raids, escorts |
| `rules/movement.js` `rules/diplomacy.js` | speeds, roads and rail, paths, orders, split and merge, supply; relations, wars, peace, coalitions, spies |
| `rules/territory.js` | territory sales: a province's value, what may be sold, the price floors, the resale lock, offers and answers, the AI as a buyer |
| `rules/combat.js` `rules/air.js` `rules/vision.js` | battles and captures; air wings, drops, missiles, satellites; fog of war |
| `rules/ai.js` `rules/tick.js` | the computer players; the hourly step `tick()` |
| `rules/api.js` | `IM.api`: the names a host calls (`newGame` `restore` `saveJSON` `tick` `S` `G` and the order functions). Names only, no logic |

The boundary:

- A rules file has no DOM, canvas, `window`, `localStorage`, sound, timer, camera or `Math.random` code. Dice go through `rng()` (its state is `S.rs`, part of the save), so a seed replays exactly.
- Rules report what happened with `IM.emit(...)`; the page subscribes with `IM.on(...)` (the `RULES EVENTS` block next to boot in `index.html`) and draws, plays sounds and saves as before. Handlers never call `rng()` and never change rule state.
- The rules files are global scripts and share one scope. The page's own script is wrapped in `(() => { ... })();`, so the page can call any rule by its bare name, but a rules file cannot see a page name: the browser enforces the boundary. Tests reach page internals through `window.__im` (test build only), and rule names directly.
- The rules name no player. A **seat** is a nation a person plays: its `ai` flag is off, and `newGame(seed, pick, seats)` takes the list (none unless given: `tools/headless.js` runs with no seat, `--seat N` with one that gives no orders; the page passes its own). The AI plays every nation that is not a seat. Orders and the seat's dealings take the nation as their first argument (`postOffer(n, ...)`, `tradeOpen(n, ...)`, `sendGift(me, n, gift)`, `aiReply(me, n, text)`, `dealOK(me, ai, deal)`, `tribute(me, m)` ...).
- What a person is told is addressed to a seat: `tell(n, text, kind, p)` (a dispatch, kept in the seat's list), `refuse(n, why)`, `cue(n, sound)`, `alarm(n)`; `tellAll` words a piece of news for each seat. Standing orders that only people give (stances, rally points, repeat production, arrival merges, the advisor's warnings, battle reports, statistics, the morning paper) run for every seat, never for "seat 0". The page has `const PLAYER = 0` of its own and shows what is addressed to it.
- A seat's records (dispatches, statistics, tutorial flags, advisor notes, papers, rally points, offers, chats, reports) are reached through `desk(n)`. The first seat's are the fields of `S` they always were, so the save format is unchanged and old saves load; another seat's are in `S.desks[n]`. One thing is still kept once per game: the verdict `S.over` (the first seat to win or lose ends the game). A multiplayer game needs a verdict per seat.
- Fog of war is per nation: `visibleSet(n)` is what nation `n` sees, `armyVisible(a, vis)` reads whose view `vis` is. The rules never decide what a client shows: map effects (`fx`, `fxStrike`, `fxMissile`, `fxWreck`, ...) are sent with who did it and where, and the page keeps the ones its seat did or can see.
- The rules read nothing from the client. What used to be asked through `IM.hook` is now an argument of the order or the preview: `odds(a, t, foes, dirs, via)` (the province a planned route enters from), `airCheck(a, p, surprise)` (the nations a confirmed surprise attack covers), `splitPlan(a, plan, spot)` (where the stack's counter is drawn). Aircraft spot from where they are at the hour (`flightPos`), not from where they are drawn.

The checks:

- `node tools/headless.js` runs the rules in plain Node with no browser: it loads `world.js`, `nations.js`, `lines.js` and the rules files in the page's order, starts a world game, lets the AI play all nations for 30 days and prints a summary (nations alive, provinces per nation, wars, units, provinces captured, dice state, state hash). Options: `--days N`, `--seed N`, `--seat N` (nation N is a seat that gives no orders; its dispatches are counted). `node tools/headless.js --check` plays the same seed twice from scratch and exits 1 unless both summaries and state hashes are equal (about 30 s). Compare Node with Node only: Node and Chromium differ in the last digit of a few floats.
- `node tools/nations-balance.js` (plain Node, several minutes) plays the nations world with every nation on the computer, 5 seeds of 60 days, and prints one PASS or FAIL line per test of `docs/NATIONS-PLAN.md` 5.2 (structure, opening, survival, no runaway, tier fairness, speed, same seed same game, seats) and the step's own checks; `--quick` runs the tests that need no game (seconds), `--table` prints every nation's opening, `--long` the two 300-day games. `node tools/headless.js --nations` runs the nations world instead of the classic one (`--check` works with it).
- `node tools/eco-check.js` (plain Node, a few seconds) checks the city-resource economy of `docs/ECONOMY.md`: every city has one main resource and it is the same on every load, the Army Base gives no income, the Arms Industry adds 25% per level at the listed prices, every playable nation of the three scenarios has an income of every good and can pay for its basic units on day 1, and an old save with a Refinery, a Foundry under construction, a knocked-out Rare Earth Mine and Economy research loads with the refunds and keeps its research bonus.
- `node tools/export-lab.js` (plain Node, about a minute) plays three seeds with one nation as a seat that only keeps a sell offer on the Market and prints what the AI nations bought from it (exit 1 under 150 units in 30 days); `node .test/eco-rep1.js` checks the Market lists, the goods filter, the offer toast, the no-city hints, the kept Economy research and the defeat text in the page.
- `node tools/x1000-check.js` (plain Node, one to two minutes) proves the resource scale (`RES_K` in `rules/data.js`: every quantity of oil, materials, iron, electronics and rare materials is 1,000 times the old number; money and manpower unchanged) changes no decision: it plays 30 days of three seeds in the classic and the nations world with origin/master's rules (unpacked with git archive; or `--base <commit>`) and with the rules on disk, and compares every day's dice, units, provinces, battles, research, money and goods divided by `RES_K`, and the whole saved state at the end. Options `--days`, `--seeds 12345,7`, `--worlds world`, `--jobs`, `--tmp <dir>` (where the base is unpacked). `node .test/x1000-oldsave.js` checks the saves: a save of the base build (no `S.rk`) loads with its goods x1000 once and plays on exactly as in the base build, a save of this build loads unchanged.
- `node tools/split-lint.js` must exit 0: no page name, browser global, unknown global, `Math.random`, `PLAYER`, `IM.hook` or `IM.cfg` in a rules file, no load-order problem, no name declared twice (it needs the `acorn` parser: `require('acorn')` or `/opt/node-tools`). `node tools/split-names.js` checks that no top-level name hides a browser global.
- `node tools/split-golden.js 20` plays 20 fixed-seed days in the browser and compares one hash of the whole state per day with `tools/golden-12345.txt`. A change that is not meant to alter the rules must not change it; a change that is meant to must record a new golden file and say so in its commit.
- The build copies every rules file the page loads to `dist/test/rules/` and `dist/public/rules/`, strips the markers the same way as in `index.html`, and checks them like the page. A `.js` file in `rules/` that the page does not load fails the build.
- `node .test/seats.js` (plain Node) plays a game with two seats that are not nation 0: the AI leaves both alone, each gets its own dispatches, records and fog of war, and orders work with the nation as an argument.
- `bash tools/mkpage.sh` copies `rules/` to `.test/rules/` for the tests.
- `tools/split-plan.js`, `tools/split-move.js` and `tools/split-perf.js` are the tools the split was done with (which declaration went to which file, the verbatim mover, a speed comparison); they are kept for reference.

To publish, upload from `dist/public/`: `index.html`, `world.js`, `nations.js`, `lines.js`, `coast.js`, `coast-hi.js`, `units3d.js`, `fx.js`, every file in `rules/` (17 files, at `rules/<name>.js`), and `assets/`.


## Rules speed

The rules run a day of the nations world (68 nations, about 4,000 units) in about half the time they took before (`node tools/perf.js` prints the numbers), and the page runs an hour over several frames. Nothing in the rules decides differently: every change below gives the same game, which `node tools/headless.js --check`, `node tools/split-golden.js` and the state hashes of `node tools/perf.js` (both worlds, and `--sliced`) prove.

- **The tick's lookups** (`rules/core.js`). While a tick runs (`tickQ`: `tickDepth > 0`) only rule code changes the state, so the scans the rules repeat most are kept and handed out again until a rule changes what they hold: the forces in a province (`byAt(p)`, `armiesAt`, `rules/combat.js`), the forces of a nation (`armiesOf(n)`, `rules/state.js`; a force's owner never changes), the provinces a nation holds (`ownedBy(n)`), each nation's wars (`warsOf`), the standing capitals (`isCapital`) and every nation's score. Each returns exactly the list its scan would, in the same order. A rule that moves a force to another province calls `atMove(a, p)` (never `a.at = p`), one that changes a province's owner calls `ownChanged()` after it, and one that changes a relation or ends a nation calls `relChanged()`; `addArmy` keeps the force lists up to date itself, and a new `S.armies` (removeEmpty) starts them again. Every tick step starts them afresh, so a test or the page may change the state between ticks; outside a tick each lookup is worked out from the state on every call.
- **Unit sums written out** (`count`, `groundN`, `shipsN`, `armyHP`, `effHP`, `hasUnits`, `power`, the healing `healW`): a named property is read many times faster than `u[UT[i]]`. The sums run in `UT` order, so every result is the same; they are only used while the unit types are exactly the ones written out (`UT_ROLL`, else the loops), so a new unit type needs no change there, only the loops' speed.
- **Relations**: the key string of each pair of nations is made once (`rkeyC`); `relAll()` says when every pair has its entry in `S.rel`, so `atWar` creates nothing and may be read in any order (the daily round of trust between computer nations then reads every war once, not n x n x n times). Entries are never removed, so once `relAll()` is true for an `S.rel` it stays true without a new check every tick step.
- **Ranged fire at peace** (`rangedStep`, `rules/combat.js`): a force fires only at forces of a nation it is at war with, so when `relAll()` holds, a nation at war with nobody (`inWar`, worked out once per nation a step) neither fires nor goes into the targets' grid (`rangedGrid(foe)`). Every force that can fire or be fired at is handled exactly as before (the same targets in the same order, the same rolls); a world at peace no longer builds the grid of all its forces four times an hour.
- **Supply** (`computeSupply`, `rules/movement.js`): the search walks each province's neighbours and leg lengths as typed arrays in the order of its `P.nb` (`nbArrays`, made once per map) instead of the Map's entries; the sum is the same, term by term.
- **The convoys' sea routes** (`convoyDay`, `rules/economy.js`): a route between two sea zones depends only on the map and the sea legs' costs (fixed per map: links are land only, the sea lanes come from the map), so `findPath` keeps it in a memo the caller hands it (keyed by from, to, movement type and the heuristic's floor; handed out as a copy) and works it out once instead of every day. A check run that also searched every route afresh found the same route in all of about 200,000 daily searches (30 days, seeds 12345, 7 and 2026, both worlds).
- **One answer per call or per turn**: a route asks `canEnter` once per owner (`pathFor`), the supply search starts from the list of cities, the computer turn counts the enemy's sea routes once (`AIT`), its offensive search (`aiTarget`) runs on flat arrays apart from the long `aiTurn`.
- **The hour over several frames** (`rules/tick.js`). The hour is a list of steps (`tickHourG`, a generator: it pauses after the morning's chores, after movement and ranged fire, after the battle and upkeep, after the captures, inside the daily round and after each computer nation's turn). `tickHour`, `tickQ` and `tick` run all of it at once as before; the page's game loop calls `tickQSlice(more)`, which runs steps while `more()` says its frame has time left (`TICK_MS`, 8 ms) and goes on in the next frames, paused or not, so no frame waits long for the rules. The steps and their order are the same either way. Between the steps the page only reads: the answers the rules keep for an hour (income, power, borders, ports, fog, ...) are then worked out without being kept (`keep()`), so the hour's own first use still makes the hour's answer. Running game time (`tickQ`, `tick`), saving (`saveJSON`), loading (`restore`) and a new game first finish an hour in progress. `node tools/perf.js --sliced` plays every hour a step at a time with such reads between the steps: the state hash must not change.
- **Drawing**: when only the fog (what your forces see) or the owners of some provinces changed (an hour passed, captures anywhere in the world), the map layer is redrawn only where it changed (`visDirty` in `index.html`: the provinces that changed hands or came into or left sight, with their neighbours, and every sight range that is new or gone), not whole; a full render when those parts cover much of the layer, or when war and peace with you changed.
- **The label pass** (`draw`, every frame): the names, building trays, building pictures and power names are placed against the boxes already claimed (counters, controls, names). Those boxes are indexed in a coarse grid as they are pushed (`bxNear`; the cities' points the same way, `cpNear`), so a test visits only the boxes near its rect, in the order they were pushed: every placement is the one a scan of the whole list gives (a box sharing no grid cell with a rect cannot overlap it). Text widths are kept per font and text (`mtw`, forgotten when the web fonts load), and the power names' spot tests are kept while the view only pans (`NAMEC`: the spots are offsets from each name's anchor). The label pass went from about 8 ms to about 3.5 ms a frame on the desktop.
- **Panning** (`shiftLayer`, `stripPump`): the layer is shifted when the view has used half its margin, and the strips it exposes (off screen, in the margin) are queued in pieces of about 360 px and rendered over the next frames, one every other frame (more while 4 ms last), nearest the screen first; a piece the screen shows or is about to show is rendered at once, and all of them before the layer is drawn scaled (a zoom). A strip or a small box renders its overlay, fog and tint passes on scratch canvases the size of the rect (`RPX`, an exact whole-pixel shift) instead of the layer-sized ones: a canvas drawn from and then changed again before the frame is shown is copied whole.
- **A finished road or railway** (`LINKD`): the layer is redrawn in boxes round the links whose road or rail level changed since the layer was made (`linkSnap` / `linkDiff`, through `visDirty`), not whole in one frame (that took 330-360 ms on the desktop every few game hours at 4x and 8x). A shifted layer (`shiftLayer`) keeps the fog, owners, tones, pixel ratio and links it was drawn with (the spare canvas kept those of an older picture, so after a pan the next hour's change made a full render).
- **The idle warm-up** (`cityWarm`): its first statement had slipped into a comment ('Cities repair 7'), so it never ran (it threw every frame); it runs again while the view is still and stops at 80% of the kept cities' budget (`cityKeepMax`), so memory stays bounded.
- `node tools/perf.js` (plain Node) times both worlds (`--world nations|classic`, `--days`, `--seed`): ms per game day in wall and CPU time and the state hash, then a second run with a clock on each listed rules function (CPU ms per day, exclusive of the other listed functions). `node .test/perf-ui.js` (browser; `--phone` for 390x844 with the CPU throttled x4) plays 10 days of the nations world in the page, lets the map settle and measures fps idle, panning and with the clock running at 1x, 4x and 8x, the main-thread time per frame by drawing phase, the rules' time per hour and the most of it in one frame, long tasks and full layer renders.

Every file in `tools/` (none of them is published; the game never loads them):

## Effects module

The map effects live in `fx.js`, not in `index.html`: the particle system (smoke, fire, flashes, dust, sparks), tracers, shells and missiles in flight, the art bursts and craters, the strike and blast effects (WFX), the battle fire from the figures (BFX), the battle smoke (BSM) and the crossed-swords badge. `fx.js` is a plain script loaded after `units3d.js`; it defines one global, `IMFX(PG)`, which the page calls once (`const FXM = window.IMFX(FXH)`, where the effects code used to be).

- `PG` (the page's `FXH`) is the effects' read-only view of the page: getters for the camera (`view`, `toScreen`, `screenToWorld`, `zx`, `wrapSX`, `wrapPx`), the canvas (`ctx`, `MCTX`, `cv`, `cw`, `ch`, `dpr`, `layer`), the settings (`SET`, `saverOn`, `afxReduced`), the redraw scheduler (`redraw`, `animFast`, `animAmb`), the sound (`AC`, `muted`, `shotAt`, `sfx`), the light (`sunSinEl`, `nightAtX`) and a few drawing helpers. Every page name the module reads is written `PG.<name>`.
- `IMFX` returns the effects' functions and tables (`emit`, `explode`, `shoot`, `FXW`, `wfxStrike`, `drawWFX`, `bfxFigure`, `figVolley`, `drawBattleSmoke`, `battleBadge`, ...); the page destructures them and calls them as before. The rules' map events (`IM.on('fxRanged' ...)` and the rest) are wired to them in the page's RULES EVENTS block.
- The rules state (`S`, `G`, the fog of war `visibleSet` / `armyVisible`) is read directly (they are globals); the effects never change it and never call `rng()`. `.test/fx-determinism.js` checks it: the same seeded game gives the same state hash with Effects High, Low and Off and with the Battery saver on or off.
- What it holds besides the effects moved from the page: firing by weapon (`cfxFire(weapon, from, to, {aid, bid, hit, kill, from, sea})`: tank art mlrs inf ship cruise ballistic icbm fighter bomber drone swarm recon sam), impacts sized S/M/L/XL (`impact`, `strikeAt`, `destroyed`, `airBurst`, `splash`), the forces' reactions (`unitAnim`: facing, recoil, hit flash and shake, a ship's rock, applied by the page to pictures, models and counters), the missiles in flight and the missile warning (`drawMissiles`, `drawWarn`), the attack-order and tap markers (`orderMark`, `drawMarks`, `tapCombat`), the drawn aircraft flight (`flightStep`, used by the page's `wingVis`) and the effect sounds (`snd`: fire, flight and impact slots, synthesized). Particles (`PART`: the firing particles at most about 150 on High, 60 on Low; smoke its own budget, 900 / 300; none with Effects Off) and shots (`PROJ`) are pools of reused objects; only what is on screen keeps the map redrawing (`fxLive`, `mslOn`). Scorch marks fade out after about 20 real seconds (`CRATER_MS`), except the tactical nuke's and the ICBM's craters (game hours). The rules' `fxAD` event (drones downed by air defence: how many, by which forces) shows interceptor streaks meeting the drones.
- Effects quality is `SET.fx` (`high` | `low` | `off`, `fxLv()` 2/1/0; the Battery saver and reduced motion count as Low); the default is High on desktops and Low on phones until the player picks one. The map's own detail is lightened only by a setting picked by hand (`mapLite`). `SET.shake` and `SET.fxSnd` turn the screen shake and the effect sounds off.
- Its checks (test build, `bash tools/mkpage.sh` first): `node .test/fx-determinism.js [days]` (the rules state is the same with every effects setting), `node .test/cfx-shots.js [W H dpr] [outdir]` (3 frames per weapon), `node .test/cfx-flight.js` (no jump, nose on the path, bank, take-off and landing speeds, the patrol loop), `node .test/cfx-ui.js` (the Effects test panel, the order marker, the tap, the missile warning, Effects Off, the settings), `node .test/cfx-perf.js [W H dpr throttle secs]` (frame times and particle counts in a busy battle), plus `.test/fx-anchor.js` and `.test/bfx-anchor.js`.

## Markers

Code that only the test build may contain goes between markers in `index.html`, `units3d.js`, `fx.js` and `rules/*.js` (the build strips all of them; the other map scripts have no markers and are copied as they are):

| Kind | JS / CSS | HTML |
|---|---|---|
| Developer mode | `/*@DEV*/ ... /*@ENDDEV*/` | `<!--@DEV--> ... <!--@ENDDEV-->` |
| Test and debug hooks | `/*@TEST*/ ... /*@ENDTEST*/` | `<!--@TEST--> ... <!--@ENDTEST-->` |

- The test build removes only the marker comments and keeps everything between them.
- The public build removes the markers and everything between them. If a marker stands alone on its line, the whole line goes.
- Blocks never nest, and every block opens and closes with the same kind and syntax. The build stops with an error otherwise.
- Fence whole statements, such as `/*@DEV*/if (DEV.reveal) return true;/*@ENDDEV*/`, so the code still parses when a block is removed. Never put a marker inside an expression.
- Developer rule overrides sit next to the rules they change (`devFill` / `devDone` / `devHour` / `devResearchAll` / `devSpawn` at the end of `rules/production.js`, the reveal override in `visibleSet` / `armyVisible`). The switches they read, `DEV` and `DEV_FILL`, are in `rules/core.js`; the page loads the saved switches into `DEV` from `localStorage` and keeps `DEV_KEY`, `DEV_SPEEDS` and `devSave`. They always call the game's own rule functions: `startResearch`, `researchHour`, `consHour`, `prodHour`, `engHour`, `addArmy`. The panel sits with the UI code next to `setSpeed`.
- If you add a dev-only name, add it to `DEV_NAMES` in `tools/build.js` so the public check catches any reference left outside a block.
- Test hooks are `@TEST` blocks too: `window.__im` and its `file://` extensions, the debug collections (`TMDBG`, `PGHOST`, `LAYEV`, `window.__dbgBoxes` with `tagDbg` / `pnDbg` / `labDbg`, the layout timers `PLAY_MS` / `PLAY_N`), the `?bake` page used by `tools/bake-assets.js` (the script that sets `window.__BAKE` and every statement that reads it, in `index.html` and `units3d.js`), and the `?artall` switch (loads every optional art file). A test or debug global is named `window.__<name>`; declare and read it only inside `@TEST` blocks.

## What the build checks

After writing both folders, `tools/build.js` checks the public build and exits non-zero if any check fails:

- no marker text is left;
- none of the developer or test names in `DEV_NAMES` appear (`DEV`, `devPanel`, `devSpawn`, `__im`, `TMDBG`, `__BAKE`, ...), in the page, in any of the five scripts or in any rules file;
- no `window.__<name>` global is read or set anywhere (a generic check, so a new debug switch left outside a block fails the build even before it is added to `DEV_NAMES`);
- every inline `<script>` parses (`vm.Script`), and so do the stripped `units3d.js` and every rules file;
- the public page is smaller than the test page.

It also checks that the test build has no marker text left and that its scripts parse. At the end it prints the sizes and the number of blocks it stripped.

## Developer mode (test build only)

The **DEV** badge sits next to the speed control. Click it, or press `` ` ``, to open the panel:

- **Instant research**: any research you start completes at once. **Research all** gives you every technology for free.
- **Instant building and production**: construction, unit training, missiles and unit upgrades finish at once, even while the game is paused.
- **Unlimited resources**: all seven resources are topped up to 500,000 every game hour. **Fill stocks** tops them up once.
- **Reveal map**: no fog. Every province is in sight and every force is identified, including submerged submarines and special forces.
- **Game speed**: 16×, 50× and 100×. These buttons also appear in the top bar on wide screens. Press `9` to cycle through them.
- **Spawn unit**: pick a unit type, an owner (any living nation; you by default) and a count. Press **Place**, then click provinces on the map. Ground and air units can go on land; ships can go at sea or on a coast. Press Esc to stop placing.

The switches are saved in this browser under the localStorage key `iron-meridian-dev`. When a switch is off, its rule is unchanged.

## Tests

- `bash tools/mkpage.sh` builds `.test/page.html` from `index.html`. The markers are comments, so this page is the test build. All the existing `node .test/<name>.js` tests and `node tools/smoke.js` run on it.
- Stealth Bomber: `node .test/stealth.js` (plain Node, about 4 minutes; `quick` skips the 80-day game) checks the unit's numbers, the two research projects (Stealth Bombers needs both Strategic Bomber Upgrade and Stealth Airframes: `req` and `req2`, read through `techReqs` / `techOpen`), the detection rates measured over hundreds of raids, the bomb load, the fog rule and the AI's limits; `node .test/stealth-ui.js` checks the research tree, the Mobilize list and what the map draws (it reads `window.__airSeen`, a test hook); `node .test/stealth-play.js` plays 5 days in developer mode with stealth raids.
- `node .test/devplay.js` loads `dist/test/play.html`, turns on every developer switch, spawns land, sea and air units for you and for an AI nation, plays at least 5 game days at 50×, and reports the checks and any console errors. It saves screenshots to `.test/dev-*.png`.
- `node .test/public-smoke.js` serves `dist/public` over http and loads it at desktop and phone sizes. It plays a game day at 8× and checks that there is no `window.__im`, no DEV badge or panel, no developer speeds and no console errors.
- Battery saver and redraw scheduling: `node .test/battery.js` prints draws per second and main-thread busy time while idle, running at 1× and panning (desktop and phone, saver off and on), checks that nothing keeps the map redrawing after a zoom out and that a pointer leaving the window clears the hover (`ONLY=stuck` runs just that part), checks the background pause, and logs the images requested at startup (`PAGE=page-before.html` measures an older page the same way). `node .test/rdstale.js on|off` forces a frame whenever the map was left undrawn and fails if it looks different (a change that did not ask for a frame). `node .test/lazyart.js` checks that building pictures load only when shown and keep their size. `node .test/rdwhy.js` lists what kept the map drawing while idle. Tests that compare screenshots of a view they jumped to can wait for `__im.mapBusy()` to turn false (no bands, detail tiles or city bakes left), as `v3r2.js` does. `node .test/anchor-check.js` runs with the Battery saver off (`SAVER=on` to try it on).
