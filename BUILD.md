# Building Iron Meridian

One source, two builds:

```
node tools/build.js
```

| Build | Folder | What it has | Use it for |
|---|---|---|---|
| Test | `dist/test/` | the game, developer mode, and the test hooks (`window.__im` on `file://`) | playtesting and the automated tests |
| Public | `dist/public/` | the game only. Every developer and test block is removed at build time. | **publishing** |

Each folder is a complete copy: `index.html` (the page to publish), `play.html` (the same page in a full HTML document, so you can open it locally), `world.js nations.js lines.js coast.js coast-hi.js units3d.js`, the rules files `rules/*.js`, and `assets/` (without `assets/art-src`, the source art the game never loads). The assets are hard-linked to the source files where the file system allows, so they take no extra disk space. Do not edit files inside `dist/`, because a hard-linked file is the source file. `dist/` is in `.gitignore`.

**To publish, use `dist/public`:** publish `index.html` as the page, plus these files at the same relative paths. Do not publish `play.html`.

| Files | What they are |
|---|---|
| `world.js` `lines.js` `coast.js` `coast-hi.js` | map data |
| `nations.js` | the playable nations of the nations world (generated by `tools/build-nations.js`; see "The nations world" below) |
| `rules/core.js` `rules/data.js` `rules/map.js` `rules/state.js` `rules/research.js` `rules/production.js` `rules/economy.js` `rules/trade.js` `rules/movement.js` `rules/diplomacy.js` `rules/combat.js` `rules/air.js` `rules/vision.js` `rules/ai.js` `rules/tick.js` `rules/api.js` | the game rules, 16 files (publish every `.js` file in `dist/public/rules/`) |
| `units3d.js` | unit models |
| `assets/` | pictures, flags and sounds |

## The nations world

Two worlds are on the start screen while the nations are rolled out region by region (`docs/NATIONS-PLAN.md`): **Classic** (the 15 powers on the old rules, scenario key `world`; every old save is this world) and **Nations of the world** (scenario key `world64`).

- `nations.js` (`window.NATIONS`) lists the playable nations of the nations world: name, map country, region, tier (S, A, B, C), colour, capital and cities (province numbers of `world.js`, capital first). It is written by `node tools/build-nations.js` from the roster and the city-choice method in that tool and is never edited by hand. A rollout step opens a region by adding it to `OPEN` in the tool (and the colours and city names of its nations), then runs the tool. `--check` fails when the file on disk is not what the tool writes; `--preview` prints the cities the method picks for every nation of the roster.
- `world.js` is not changed. Which provinces are cities and capitals is switched per game by `useWorld` (`rules/map.js`): the flags of `world.js` for the classic world and every old save, the lists of `nations.js` for the nations world. A nations-world save carries its own list of cities (`S.w64`), so it keeps its world when `nations.js` grows; a save of a newer format than the build knows is refused with a message (`restore.why`).
- The tier rules are in `rules/`: the start by tier (`tierStart`, `tierCatchUp` in `rules/state.js`; the numbers are `TIER_EVEN`, `TIER_FULL` and `TIER_MODES` in `rules/data.js`), the grace by tier gap (`graceOn`), the computer's choice of victim and its limit on wars (`rules/diplomacy.js`), the victory numbers by the number of nations (`winCapsFor`, `winShareFor`, `coalCaps`). A game mode sets how far apart the tiers start: `spread` 0 is an equal start for everyone, 1 the plan's wide table. Normal mode is 0.3 (close to equal); `competitive` (0.6) is in the table for later and not offered yet.
- **Province split** (owner's answer 1; plan 4.6): the nations world plays on its own map, `world.js` with Israel, Greece, Cuba and Belarus cut into smaller provinces (21 new provinces, numbers 3465 to 3485, appended after the last province of `world.js`; each records the province it was cut from, `P.parent`). `node tools/build-provsplit.js <ne_10m_admin_1_states_provinces.geojson> <ne_10m_populated_places_simple.geojson>` (Natural Earth; `NODE_PATH` with `country-state-city` for town names, as for `tools/build-world2.js`) writes `tools/provsplit.json`: the new provinces (name, country, people, terrain, parent), the cut provinces' new name, people and terrain, the cells that move, and the river, road and rail pairs that touch a cut province (worked out from the lines of `lines.js` with the rules of `tools/build-lines.js`). `tools/build-nations.js` copies it into `nations.js` as `NATIONS.map` and chooses the cities on that map. `node tools/build-provsplit.js --check` checks the file against `world.js` and `lines.js` without the Natural Earth files.
- **Two maps**: `rules/map.js` keeps map 0 (`world.js` as it is: the classic world, the theatres, every old save and a nations-world save made before the split) and map `MAP_NEW` (with the split), each loaded once when first needed (`mapOf`); `useMap` makes one the map in use (`G`) with a new game or a load. A save names its map (`S.map`; absent for `world.js`). On the split map every province of `world.js` keeps its deposits, city ground, sea straits and the per-province yield scale exactly as on `world.js`; only the new provinces draw their own. The page hears `world` and hands the terrain texture, lakes, land mask and sea from one map to the other, and makes again what hangs on provinces (lines, lake-side labels, every town's footprint and bakes, trays, the cached layer); the start screen counts the nations world on its own map (`onMap`).
- Nothing of this runs in the classic world: `node tools/split-golden.js 20` and `node .test/nat-oldsave.js` (a save made by the build before the nations world plays on to the same state in the old and the new build) prove it. `node .test/nat-world.js` goes back and forth between the two maps in one page; `node .test/nat-split-shots.js <dir>` shows the four countries on both maps and taps the new provinces.

## Rules files

The game rules live in plain scripts in `rules/`, not in `index.html` (owner task 5, finished in step 10). The page loads them with `<script src="rules/x.js">` after the map data and before its own script, in this order:

| File | What it holds |
|---|---|
| `rules/core.js` | the namespace `IM` and its event sink (`IM.on` / `IM.emit`); seats (`isSeat` `seats` `desk`); the reports, each addressed to a seat (`tell` `tellAll` `refuse` `cue` `alarm` `fxAt` `bump`) |
| `rules/data.js` | tables and constants (units, missiles, resources, terrain, buildings, research, doctrines), the seedable dice `rng()`, hex-grid maths |
| `rules/map.js` | the world: provinces, neighbours, straits, links, resources, seasons and weather |
| `rules/state.js` | scenarios, `newGame`, `saveJSON`, `restore` and the old-save upgrades |
| `rules/research.js` `rules/production.js` | research slots; costs, building, mobilizing, training |
| `rules/economy.js` `rules/trade.js` | yields, income, market and order book, unrest; trade routes, raids, escorts |
| `rules/movement.js` `rules/diplomacy.js` | speeds, roads and rail, paths, orders, split and merge, supply; relations, wars, peace, coalitions, spies |
| `rules/combat.js` `rules/air.js` `rules/vision.js` | battles and captures; air wings, drops, missiles, satellites; fog of war |
| `rules/ai.js` `rules/tick.js` | the computer players; the hourly step `tick()` |
| `rules/api.js` | `IM.api`: the names a host calls (`newGame` `restore` `saveJSON` `tick` `S` `G` and the order functions). Names only, no logic |

The boundary:

- A rules file has no DOM, canvas, `window`, `localStorage`, sound, timer, camera or `Math.random` code. Dice go through `rng()` (its state is `S.rs`, part of the save), so a seed replays exactly.
- Rules report what happened with `IM.emit(...)`; the page subscribes with `IM.on(...)` (the `RULES EVENTS` block next to boot in `index.html`) and draws, plays sounds and saves as before. Handlers never call `rng()` and never change rule state.
- The rules files are global scripts and share one scope. The page's own script is wrapped in `(() => { ... })();`, so the page can call any rule by its bare name, but a rules file cannot see a page name: the browser enforces the boundary. Tests reach page internals through `window.__im` (test build only), and rule names directly.
- The rules name no player. A **seat** is a nation a person plays: its `ai` flag is off, and `newGame(seed, pick, seats)` takes the list (none unless given: `tools/headless.js` runs with no seat, `--seat N` with one that gives no orders; the page passes its own). The AI plays every nation that is not a seat. Orders and the seat's dealings take the nation as their first argument (`postOffer(n, ...)`, `tradeOpen(n, ...)`, `sendGift(me, n, gift)`, `aiReply(me, n, text)`, `dealOK(me, ai, deal)`, `tribute(me, m)` ...).
- What a person is told is addressed to a seat: `tell(n, text, kind, p)` (a dispatch, kept in the seat's list), `refuse(n, why)`, `cue(n, sound)`, `alarm(n)`; `tellAll` words a piece of news for each seat. Standing orders that only people give (stances, rally points, repeat production, arrival merges, the advisor's warnings, battle reports, statistics, the morning paper) run for every seat, never for "seat 0". The page has `const PLAYER = 0` of its own and shows what is addressed to it.
- A seat's records (dispatches, statistics, tutorial flags, advisor notes, papers, rally points, offers, chats, reports) are reached through `desk(n)`. The first seat's are the fields of `S` they always were, so the save format is unchanged and old saves load; another seat's are in `S.desks[n]`. One thing is still kept once per game: the verdict `S.over` (the first seat to win or lose ends the game). A multiplayer game needs a verdict per seat.
- Fog of war is per nation: `visibleSet(n)` is what nation `n` sees, `armyVisible(a, vis)` reads whose view `vis` is. The rules never decide what a client shows: map effects (`fx`, `fxStrike`, `fxMissile`, `fxWreck`, ...) are sent with who did it and where, and the page keeps the ones its seat did or can see.
- The rules read nothing from the client. What used to be asked through `IM.hook` is now an argument of the order or the preview: `odds(a, t, foes, dirs, via)` (the province a planned route enters from), `airCheck(a, p, surprise)` (the nations a confirmed surprise attack covers), `splitPlan(a, plan, spot)` (where the stack's counter is drawn). Aircraft spot from where they are at the hour (`flightPos`), not from where they are drawn.

The checks:

- `node tools/headless.js` runs the rules in plain Node with no browser: it loads `world.js`, `lines.js` and the rules files in the page's order, starts a world game, lets the AI play all nations for 30 days and prints a summary (nations alive, provinces per nation, wars, units, provinces captured, dice state, state hash). Options: `--days N`, `--seed N`, `--seat N` (nation N is a seat that gives no orders; its dispatches are counted). `node tools/headless.js --check` plays the same seed twice from scratch and exits 1 unless both summaries and state hashes are equal (about 30 s). Compare Node with Node only: Node and Chromium differ in the last digit of a few floats.
- `node tools/nations-balance.js` (plain Node, several minutes) plays the nations world with every nation on the computer, 5 seeds of 60 days, and prints one PASS or FAIL line per test of `docs/NATIONS-PLAN.md` 5.2 (structure, opening, survival, no runaway, tier fairness, speed, same seed same game, seats) and the step's own checks; `--quick` runs the tests that need no game (seconds), `--table` prints every nation's opening, `--long` the two 300-day games. `node tools/headless.js --nations` runs the nations world instead of the classic one (`--check` works with it).
- `node tools/eco-check.js` (plain Node, a few seconds) checks the city-resource economy of `docs/ECONOMY.md`: every city has one main resource and it is the same on every load, the Army Base gives no income, the Arms Industry adds 25% per level at the listed prices, every playable nation of the three scenarios has an income of every good and can pay for its basic units on day 1, and an old save with a Refinery, a Foundry under construction, a knocked-out Rare Earth Mine and Economy research loads with the refunds and keeps its research bonus.
- `node tools/export-lab.js` (plain Node, about a minute) plays three seeds with one nation as a seat that only keeps a sell offer on the Market and prints what the AI nations bought from it (exit 1 under 150 units in 30 days); `node .test/eco-rep1.js` checks the Market lists, the goods filter, the offer toast, the no-city hints, the kept Economy research and the defeat text in the page.
- `node tools/split-lint.js` must exit 0: no page name, browser global, unknown global, `Math.random`, `PLAYER`, `IM.hook` or `IM.cfg` in a rules file, no load-order problem, no name declared twice (it needs the `acorn` parser: `require('acorn')` or `/opt/node-tools`). `node tools/split-names.js` checks that no top-level name hides a browser global.
- `node tools/split-golden.js 20` plays 20 fixed-seed days in the browser and compares one hash of the whole state per day with `tools/golden-12345.txt`. A change that is not meant to alter the rules must not change it; a change that is meant to must record a new golden file and say so in its commit.
- The build copies every rules file the page loads to `dist/test/rules/` and `dist/public/rules/`, strips the markers the same way as in `index.html`, and checks them like the page. A `.js` file in `rules/` that the page does not load fails the build.
- `node .test/seats.js` (plain Node) plays a game with two seats that are not nation 0: the AI leaves both alone, each gets its own dispatches, records and fog of war, and orders work with the nation as an argument.
- `bash tools/mkpage.sh` copies `rules/` to `.test/rules/` for the tests.
- `tools/split-plan.js`, `tools/split-move.js` and `tools/split-perf.js` are the tools the split was done with (which declaration went to which file, the verbatim mover, a speed comparison); they are kept for reference.

To publish, upload from `dist/public/`: `index.html`, `world.js`, `lines.js`, `coast.js`, `coast-hi.js`, `units3d.js`, every file in `rules/` (16 files, at `rules/<name>.js`), and `assets/`.

## Markers

Code that only the test build may contain goes between markers in `index.html`, `units3d.js` and `rules/*.js` (the build strips all of them; the other map scripts have no markers and are copied as they are):

| Kind | JS / CSS | HTML |
|---|---|---|
| Developer mode | `/*@DEV*/ ... /*@ENDDEV*/` | `<!--@DEV--> ... <!--@ENDDEV-->` |
| Test and debug hooks | `/*@TEST*/ ... /*@ENDTEST*/` | `<!--@TEST--> ... <!--@ENDTEST-->` |

- The test build removes only the marker comments and keeps everything between them.
- The public build removes the markers and everything between them. If a marker stands alone on its line, the whole line goes.
- Blocks never nest, and every block opens and closes with the same kind and syntax. The build stops with an error otherwise.
- Fence whole statements, such as `/*@DEV*/if (DEV.reveal) return true;/*@ENDDEV*/`, so the code still parses when a block is removed. Never put a marker inside an expression.
- Developer rule overrides sit next to the rules they change (`devFill` / `devDone` / `devHour` / `devResearchAll` / `devSpawn` at the end of `rules/production.js`, the reveal override in `visibleSet` / `armyVisible`). The switches they read, `DEV` and `DEV_FILL`, are in `rules/core.js`; the page loads the saved switches into `DEV` from `localStorage` and keeps `DEV_KEY`, `DEV_SPEEDS` and `devSave`. They always call the game's own rule functions: `startResearch`, `researchHour`, `consHour`, `prodHour`, `engHour`, `addArmy`. The panel sits with the UI code next to `setSpeed`.
- If you add a dev-only name, add it to `DEV_NAMES` in `tools/build.js` so the public check catches any reference left outside a block.
- Test hooks are `@TEST` blocks too: `window.__im` and its `file://` extensions, the debug collections (`TMDBG`, `PGHOST`, `LAYEV`, `window.__dbgBoxes` with `tagDbg` / `pnDbg` / `labDbg`, the layout timers `PLAY_MS` / `PLAY_N`), the `?bake` page used by `tools/bake-assets.js` (the script that sets `window.__BAKE` and every statement that reads it, in `index.html` and `units3d.js`), and the `?artall` switch (loads every optional art file). A test or debug global is named `window.__<name>`; declare and read it only inside `@TEST` blocks.

## What the build checks

After writing both folders, `tools/build.js` checks the public build and exits non-zero if any check fails:

- no marker text is left;
- none of the developer or test names in `DEV_NAMES` appear (`DEV`, `devPanel`, `devSpawn`, `__im`, `TMDBG`, `__BAKE`, ...), in the page, in any of the five scripts or in any rules file;
- no `window.__<name>` global is read or set anywhere (a generic check, so a new debug switch left outside a block fails the build even before it is added to `DEV_NAMES`);
- every inline `<script>` parses (`vm.Script`), and so do the stripped `units3d.js` and every rules file;
- the public page is smaller than the test page.

It also checks that the test build has no marker text left and that its scripts parse. At the end it prints the sizes and the number of blocks it stripped.

## Developer mode (test build only)

The **DEV** badge sits next to the speed control. Click it, or press `` ` ``, to open the panel:

- **Instant research**: any research you start completes at once. **Research all** gives you every technology for free.
- **Instant building and production**: construction, unit training, missiles and unit upgrades finish at once, even while the game is paused.
- **Unlimited resources**: all seven resources are topped up to 500,000 every game hour. **Fill stocks** tops them up once.
- **Reveal map**: no fog. Every province is in sight and every force is identified, including submerged submarines and special forces.
- **Game speed**: 16×, 50× and 100×. These buttons also appear in the top bar on wide screens. Press `9` to cycle through them.
- **Spawn unit**: pick a unit type, an owner (any living nation; you by default) and a count. Press **Place**, then click provinces on the map. Ground and air units can go on land; ships can go at sea or on a coast. Press Esc to stop placing.

The switches are saved in this browser under the localStorage key `iron-meridian-dev`. When a switch is off, its rule is unchanged.

## Tests

- `bash tools/mkpage.sh` builds `.test/page.html` from `index.html`. The markers are comments, so this page is the test build. All the existing `node .test/<name>.js` tests and `node tools/smoke.js` run on it.
- Stealth Bomber: `node .test/stealth.js` (plain Node, about 4 minutes; `quick` skips the 80-day game) checks the unit's numbers, the two research projects (Stealth Bombers needs both Strategic Bomber Upgrade and Stealth Airframes: `req` and `req2`, read through `techReqs` / `techOpen`), the detection rates measured over hundreds of raids, the bomb load, the fog rule and the AI's limits; `node .test/stealth-ui.js` checks the research tree, the Mobilize list and what the map draws (it reads `window.__airSeen`, a test hook); `node .test/stealth-play.js` plays 5 days in developer mode with stealth raids.
- `node .test/devplay.js` loads `dist/test/play.html`, turns on every developer switch, spawns land, sea and air units for you and for an AI nation, plays at least 5 game days at 50×, and reports the checks and any console errors. It saves screenshots to `.test/dev-*.png`.
- `node .test/public-smoke.js` serves `dist/public` over http and loads it at desktop and phone sizes. It plays a game day at 8× and checks that there is no `window.__im`, no DEV badge or panel, no developer speeds and no console errors.
- Battery saver and redraw scheduling: `node .test/battery.js` prints draws per second and main-thread busy time while idle, running at 1× and panning (desktop and phone, saver off and on), checks that nothing keeps the map redrawing after a zoom out and that a pointer leaving the window clears the hover (`ONLY=stuck` runs just that part), checks the background pause, and logs the images requested at startup (`PAGE=page-before.html` measures an older page the same way). `node .test/rdstale.js on|off` forces a frame whenever the map was left undrawn and fails if it looks different (a change that did not ask for a frame). `node .test/lazyart.js` checks that building pictures load only when shown and keep their size. `node .test/rdwhy.js` lists what kept the map drawing while idle. Tests that compare screenshots of a view they jumped to can wait for `__im.mapBusy()` to turn false (no bands, detail tiles or city bakes left), as `v3r2.js` does. `node .test/anchor-check.js` runs with the Battery saver off (`SAVER=on` to try it on).
